# SYNAPSE FIELD Rebuild Plan

> 状态：待实施
>
> 目的：保留用户满意的封面与“封面进入目录”的空间转场，重构目录卡片和章节内容，使项目成为一份可以完整播放的桌面演示文件。

## 1. 本次重构的结论

现有项目的问题不在于缺少动画，而在于把三种本应分开的东西叠在了一起：目录的三维屏风、章节视觉海报、演示正文。结果是视觉标签被重复绘制，信息层级相互遮挡，章节页也没有形成演示文稿应有的阅读节奏。

重构后的原则是：

```text
封面：氛围与命题
  -> 目录：唯一保留三维屏风的空间场景
      -> 章节：全屏、平面的独立演示文稿
          -> 结尾：回到完整空间场景
```

目录负责“选择章节”，章节负责“讲清内容”。两者不在同一屏竞争。

## 2. 已确认的问题与成因

| 现象 | 当前成因 | 重构处理 |
| --- | --- | --- |
| 从封面进入目录总是停在第三章 | `js/app.js` 中 `selectedIndex` 和 `visualIndex` 初始值均为 `2` | 初始值改为 `0`，镜头首次落在 `01 LISTENING` |
| 屏幕上持续出现不明文字 | Canvas 海报重复绘制 `SYNAPSE / xx`、`STATE / xx OF 05`、底部指标；每个屏风还有圆形编号 Sprite | 删除所有仅为“科技感”存在的海报文字和圆形编号；文字只由页面 HTML 层统一管理 |
| 目录像游戏面板或 HUD | 高饱和发光边框、金属边、圆形徽章、扫描线、过量等宽标签同时存在 | 目录卡片收敛为半透明玻璃和单一信息层；只显示章节号、英文标题、一句中文说明 |
| 章节页仍像屏风的附属品 | `chapter-visual` 直接放大目录海报，固定在正文后方 | 删除章节页对目录海报的依赖；改成独立 `deck-screen` 舞台 |
| 章节文字小，无法远距离阅读 | 正文标题最大约 52px，正文仅 14px，内容被透明 HUD 包围 | 内容页标题提升到 72 至 112px；正文 28 至 38px；数据只保留一个大指标或一组极简比较 |
| 五页内容看起来像同一页换字 | 每页复用同一 Canvas 海报，只加 `STATE` 虚线和圆弧 | 每个页面定义独立 `kind` 和布局，不再以“同一海报的不同叠层”模拟五页 |
| 自动返回缺少叙事控制 | 普通章节第五页自动返回，结尾页也自动返回 | 保留“第五页结束回目录”的目标，但将停留时间、结尾逻辑和按键行为设为明确状态，不与页面阅读冲突 |

## 3. 目标体验

### 3.1 封面

保留现有封面的核心构图、动态词槽与景深模糊。它已经建立了合适的气氛，不进入本轮大改范围。

只做两项整理：

- 背后的目录屏风改用新的克制卡片样式，使模糊后的轮廓更像展览装置。
- 动态词只在封面显示；进入目录后停止，避免任何文字在后续页面残留。

### 3.2 一级目录

目录从第一章开始。屏风仍为弧形环绕，但它像一组高级展览显示器，而不是驾驶舱仪表盘。

每个屏风卡片只保留：

```text
01
LISTENING
在噪声中找到第一条可被理解的信号。
```

当前卡片可完整展示；前后卡片只露出边缘、编号和视觉轮廓。面板本身不显示 `STATE`、`SYNAPSE`、单位、圆章、扫描线或多组小字。

目录视觉建议：

- 背景：接近黑色的蓝绿场，不铺满网格。
- 材质：低反射玻璃、细边、轻微透光；取消厚重金属框。
- 主视觉：每章仅保留一个安静的图形符号，例如波形、轨迹、闭环、曲线、开放节点。
- 色彩：冷青作为全局焦点；绿色只用于确认状态；珊瑚色仅在第三章反馈闭环中出现。
- 运动：转向时使用镜头与面板的空间关系制造动感，不使用闪烁、扫描、粒子爆发或持续跑马灯。

### 3.3 章节内容页

进入章节后，目录舞台彻底退出阅读层。镜头穿过当前面板后，面板变为一段短暂过场；过场结束，出现独立的全屏 deck。

章节页的基准是“投影屏上的演示幻灯片”，而不是透明界面。

```text
┌─────────────────────────────────────────────────────────────┐
│ 01 / LISTENING                                     01 / 05   │
│                                                             │
│                 单一、完整的主视觉舞台                       │
│                                                             │
│ FIND THE SIGNAL                                             │
│ 输入不是一条干净指令，而是一片需要被辨认的活动。               │
│                                                             │
│ 一条必要的示意说明，或一个大读数                              │
└─────────────────────────────────────────────────────────────┘
```

- 背景为全屏深色画面，不显示目录面板轮廓。
- 标题、中文解释和主视觉共处一个统一版面，不再嵌套卡片。
- 一页只回答一个问题。中文解释最多两行，演讲者负责补充细节。
- 使用大字号、高留白和固定页码；正文必须能在 1920 x 1080 投影下阅读。
- 页面之间通过内容舞台内部的淡入、推移、聚焦来转换，避免每次都重新出现整张界面。

### 3.4 结尾

第五章最后一页先停留，再进入结尾。结尾不应覆盖第五章面板上的文字，而应在镜头回退、目录屏风重新完整可见之后出现。

结尾文本保持：

```text
FROM NEURAL ACTIVITY
TO CHOICE
```

中文句：`接口可以放大信号，但决定仍然属于正在参与的人。`

结尾停留后，按下一步或自动回到目录的第五章；不直接跳回封面。

## 4. 视觉语言重定向

### 4.1 从“科技 HUD”到“科学编辑设计”

重构借鉴 `DESIGN-ASSET-LIBRARY.html` 中三类成熟模式：

- `Performance as a picture`：数据作为一张能读懂的图，而不是仪表盘堆叠。
- `Roman / pixel`：衬线字体只承载少量意义文字，等宽字体只服务于页码和数据。
- `A page that turns`：每页先建立清晰的世界，再要求观众理解系统。

不再使用的模式：

- 持续扫描线、重复网格、成片的方形粒子。
- 圆形数字徽章、金属重框、复杂霓虹折射条。
- 任何没有叙事任务的英文标签。
- 页面边缘无意义地常驻 `SYNAPSE`、`STATE`、`ARC` 等词。

### 4.2 色彩与材质

| 用途 | 处理方式 |
| --- | --- |
| 全局底色 | `#05080D`，保持深色但加入微弱青绿深度 |
| 文字 | 接近白色，正文不使用半透明灰字 |
| 冷青 | 当前信号、当前章节、标题下划线 |
| 绿色 | 仅用于“已确认”“收束”“下一步” |
| 珊瑚色 | 仅用于反馈闭环，不扩散到所有章节 |
| 玻璃 | 仅目录使用；章节 deck 不使用玻璃卡片 |

章节页的背景不能都由一个模板生成。每章应有自己的空间材质：

- 第一章：雾状波形与低亮电极点。
- 第二章：深色轨迹场和少量聚焦区域。
- 第三章：简洁闭环光带，留出黑色中心。
- 第四章：大比例曲线和很少的数据线。
- 第五章：开放节点与大面积空白。

## 6. 运行时架构重构

### 6.1 分离两个渲染模式

当前 `app.js` 同时承担目录三维场景和章节内容渲染。重构后应明确分开：

```text
Directory Stage
  - Three.js 弧形屏风
  - 只提供章节选择与进入转场

Deck Stage
  - HTML/CSS 全屏演示版式
  - Canvas 或轻量 SVG/DOM 图表
  - 不渲染目录屏风文字或面板
```

建议文件拆分：

```text
js/
  app.js                 # 状态机、键盘、全屏、阶段切换
  directory-stage.js     # Three.js 屏风、相机、目录卡片
  deck-renderer.js       # 章节幻灯片的版式和页面切换
  deck-visuals.js        # 波形、轨迹、闭环、曲线、节点场
```

如果先保持单文件，也必须以 `renderDirectory()`、`renderDeckSlide()`、`renderEnding()` 三个明确边界组织代码，禁止章节页再调用目录海报生成函数。

### 6.2 清理当前实现

以下实现应删除或替换：

- `selectedIndex: 2` 与 `visualIndex: 2` 改为 `0`。
- `createLabel()` 创建的圆形章节徽章。
- `createPoster()` 中写入的 `SYNAPSE / xx`、底部指标和状态文字。
- `drawPageOverlay()` 中虚线、圆弧和 `STATE / xx OF 05`。
- 章节页上的 `chapter-visual` 面板背景、扫描线伪元素和固定透明框。
- 目录卡片的重金属四边框与常驻高亮 shader。

保留但调整：

- 封面景深模糊与标题进入转场。
- 目录弧形位置计算和键盘左右旋转。
- 镜头穿过当前目录面板的进入动作。
- `F` 全屏、`Escape` 仅退出浏览器全屏、`ArrowUp` 返回上一级。

### 6.3 内容数据模型

章节数据改成“演示页面数据”，而不是“海报数据”。每页需要明确类型：

```js
{
  id: "listening-readout",
  kind: "waveform-readout",
  eyebrow: "01 / LISTENING",
  index: "02 / 05",
  title: "THE READOUT",
  body: "同一片活动里，只有少数变化会反复出现。",
  annotation: "示意数据，不代表临床测量。",
  data: {
    channels: "32",
    window: "480 ms",
    stability: "0.82"
  }
}
```

`kind` 决定使用哪个全屏布局和视觉函数。文本、数据、配色和视觉参数都留在配置中；状态机只处理翻页，不判断某一页的具体内容。

## 7. 交互与播放规则

| 阶段 | 下一步 | 上一步 | 特殊行为 |
| --- | --- | --- | --- |
| 封面 | 进入目录 | 无 | 首次进入目录选中第 01 章 |
| 目录 | 进入当前章节 | 回封面 | 左右切换章节，数字键直达 |
| 章节 deck | 下一张幻灯片 | 上一张幻灯片 | 第五页停留后回目录 |
| 第五章第五页 | 进入结尾 | 回第四页 | 结尾不是叠在面板上的弹层 |
| 结尾 | 回目录第五章 | 回目录第五章 | 可设置 5 至 7 秒自动回退 |

章节页内不显示键盘说明。交互应通过稳定页码、切换节奏和明显的页面变化建立可预期性。

## 8. 实施阶段

### Phase 0：建立视觉基准

1. 为当前封面、目录、章节页和结尾页分别留一张 1920 x 1080 截图。
2. 记录首屏从第 03 章开始、Canvas 文本常驻、章节页文字过小三个可复现问题。
3. 确认封面转场作为保留基准，不在后续重构中削弱。

### Phase 1：重做目录

1. 将目录初始索引固定为第 01 章。
2. 删除所有 Canvas 内的装饰文字和圆形数字徽章。
3. 重做五张目录卡片：一张主题图形、一组章节信息、一个克制的玻璃层。
4. 调整灯光、材质和面板边框，使当前卡片清晰、邻近卡片低信息量。
5. 在桌面截图中检查标题、面板和目录文案没有重叠。

### Phase 2：建立全屏 Deck 框架

1. 用新的 `deck-screen` 替代 `chapter-screen` 与 `chapter-visual`。
2. 建立标题、中文正文、页码、数据注记、主视觉舞台五个稳定区域。
3. 设定演示级字体尺度：标题 72 至 112px，正文 28 至 38px，页码 14 至 16px。
4. 章节进入后将 Three.js 目录舞台淡出到不可读，避免任何屏风或海报文字残留。
5. 完成第 01 章五页，作为全套 deck 的样板。

### Phase 3：逐章实现内容视觉

1. 实现第 02 章轨迹场和选择聚焦。
2. 实现第 03 章闭环光带和三步状态。
3. 实现第 04 章单指标曲线与三会话比较。
4. 实现第 05 章开放节点、同意、控制和语境对比。
5. 实现结尾页与第五章之间的镜头回退。

### Phase 4：演讲与阅读打磨

1. 用 1920 x 1080 与 1366 x 768 检查文字大小、换行和重叠。
2. 连续播放从封面到结尾，检查所有章节的返回路径。
3. 检查任何页面都没有遗留 `STATE`、`SYNAPSE / xx`、假数据标签或无意义小字。
4. 用全屏模式验证 `Escape`、`F`、`ArrowUp`、`Backspace` 的行为。
5. 清理测试依赖和截图，只保留可离线运行的文件。

## 9. 验收标准

重构完成时应满足以下条件：

- 从封面进入目录，默认显示第一章。
- 目录页没有遮挡正文的无意义标签，也没有重复圆形编号。
- 每个章节进入后呈现为全屏独立演示页，不再显示目录屏风背景。
- 中文正文在 1920 x 1080 投影中可从远处阅读；英文只承担视觉层级。
- 五个章节各有五张真正不同的演示页，而不是同一海报换文字。
- 普通章节第五页能稳定回到目录；第五章能稳定进入结尾再回目录。
- 所有资源继续保持本地化，复制整个文件夹到另一台电脑即可运行。
