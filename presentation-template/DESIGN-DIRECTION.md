# Presentation Template 设计方向

> 文档状态：设计重构稿 v0.2
>
> 本文定义模板的视觉方向、叙事节奏、页面系统和资产使用边界，不代表运行代码已经按本文实现。

## 0. 项目定位与名称

本文件夹名称统一为 `presentation-template`。它是一套可复用的演示文稿模板，不是某个空间效果、动效实验或单场演示的文件夹。

```text
presentation-template
    = 可复用的演示母版、页面系统与制作流程

bci-synapse-demo
    = 使用演示能力制作的一场具体内容演示
```

模板需要提供可重复使用的开场、目录、章节节奏和正文页型，承载文字、图表、流程、图片、视频与引用，并允许 AI 根据 Markdown 内容选择和填充页面。模板的价值不在于展示效果数量，而在于让内容清楚、有节奏地成为一场完整演示。

## 1. 首版设计目标

首版只做一套视觉主题，不同时建设多个主题，也不试图覆盖所有演示风格。其他视觉方向留给其他模板。

首版主题暂称 `editorial-spatial`：以编辑式研究叙事为基础，使用暖白、墨黑和砖红，整体极简；同时通过空间构图和克制的镜头运动，让开场、目录和章节转换具有纵深与连续性。

目标气质：

> **极简的编辑式研究叙事：信息准确、空间明确、视觉克制。**

关键词：

- minimal
- editorial
- spatial
- precise
- restrained
- legible

## 2. 视觉系统

### 2.1 色彩与字体

- 主背景使用暖白；需要建立舞台感或章节停顿时使用墨黑。
- 正文以墨黑为主，砖红是唯一主强调色，用于重点、标记和少量路径提示。
- 不预设冷青、草绿等其他强调色，不在首版中提供换主题选择。
- 标题可采用有性格的衬线字体，正文使用清晰的无衬线字体，数据与编号可使用等宽字体；最终字体组合通过静态样稿确认。
- 线条、编号、页码、图注和留白构成辅助层级。装饰元素必须服从信息阅读。

### 2.2 极简不等于平面

极简描述的是画面语言，不代表空间表现必须扁平。首版必须让封面进入目录的过程具备明显但克制的空间感和立体感。

空间感可以通过以下方式建立：

- 前景、中景、远景之间清楚的尺度与景深关系；
- 标题、章节路径和视觉对象在空间中的前后位置；
- 目录中的章节具有距离、层级或纵深，而不是平铺成普通列表；
- 封面元素在转场中延续、移动、推近或退远，使观众感到进入同一个演示空间；
- 使用克制的透视、遮挡、景别变化和光影塑造立体感。

空间表现的边界：

- 空间和立体感服务于观看路径，不以堆叠 3D 物件证明技术能力；
- 不将每页做成玻璃面板、HUD、霓虹界面或卡片墙；
- 正文、表格和图表保持稳定、清晰的阅读平面；
- 不使用会扭曲数据判断的透视或倾斜；
- 动效结束后所有内容必须完整、静止、可读。

### 2.3 封面进入目录：首要空间体验

封面到目录不是两个无关页面之间的淡入淡出，而是首版最重要的连续转场。

- 封面先建立主题、标题和空间尺度；
- 进入目录时，镜头或空间关系发生变化，标题、背景对象或路径中的至少一个元素延续到目录；
- 目录中的章节应有远近、层级或路径关系，避免退化成普通平面目录；
- 目录必须让观众看懂演示将如何展开，同时文字保持清楚；
- 转场应简洁、方向明确、可快速完成，不让观众等待装饰动画。

具体使用何种空间构图、对象和镜头路径，先由静态设计稿确定，再设计转场动作。空间连续性是目标，不能预先锁定某一种 3D 技术或素材。

## 3. 素材库与本地资产边界

素材库中的视觉实验可作为构图、动效和叙事关系的参考，不意味着需要将每个 demo 搬进模板。可借鉴的能力包括：

- 超大标题、字体对比、编辑网格、栏线、页码与图注；
- `dynamic-last-word` 的命题词变化方式；
- `scrollytelling` 的阶段推进关系；
- 终端叙事、数据比较与数量级变化的讲述结构；
- 线场、粒子、镜头放大、路径绘制和几何对象等空间表达方式。

`assets/imagery/backgrounds/` 中的两个 PNG，以及 `assets/imagery/posters/` 中的两个 JPG，只是演示素材，用于素材展示或临时占位，不属于首版模板的核心视觉资产，也不应成为模板设计成立的前提。首版不围绕这四张图片建立主题或页面结构。模板需要示例视觉时，应优先使用有明确内容角色、可离线携带且授权边界清楚的素材。

学习参考、网页截图和第三方页面快照不自动等于可直接使用或可再分发素材。任何实际进入演示的资产，都必须确认来源、授权、用途边界和离线可用性。

## 4. 一场演示的节奏

首版采用有限组合，而不是无限自由编辑器：

```text
一场演示
= 一套 editorial-spatial 视觉主题
+ 一个空间化开场与目录
+ 3–6 个章节
+ 6–8 种常用正文页型
+ 一套克制的转场与揭示规则
```

建议用约 20–30 页验证覆盖能力，不要求每场演示凑齐固定页数或所有页型。

| 段落 | 典型数量 | 目的 | 推荐视觉状态 |
| --- | ---: | --- | --- |
| Cover | 1 | 建立命题与气氛 | 暖白或墨黑舞台、超大标题、空间纵深 |
| Contents | 1 | 说明叙事路线 | 有空间层级的章节路径，不做平面列表 |
| Chapter open | 3–6 | 章节换气 | 墨黑或高留白、单一视觉焦点 |
| Headline / statement | 若干 | 讲清判断 | 暖白阅读页、编辑式排版 |
| Split media | 1–3 | 展示证据或材料 | 图像与文字有明确版面关系 |
| Data / comparison | 按内容需要 | 讲趋势、差异与变化 | 稳定、可读、避免透视扭曲 |
| Process / timeline | 按内容需要 | 解释步骤或阶段 | 路径清楚、连线简洁 |
| References | 0–1 | 追溯来源 | 安静、密度可控 |
| Closing | 1 | 收束或开放下一步 | 回到空间舞台，停留而不循环 |

## 5. 页面系统

页面按观众需要完成的阅读动作分类，不按视觉效果分类。

### 5.1 结构页

#### `cover`

回答：这场演示关于什么？

内容字段：主标题、副标题、汇报人 / 单位 / 日期；可选命题词和背景视觉对象。

视觉规则：

- 标题是首屏的主要信息，不放进装饰卡片；
- 以构图、尺度、景深建立开场空间；
- 背景只负责空间与气氛，不得压过标题；
- 封面必须预留与目录发生连续转场的视觉锚点。

#### `contents`

回答：接下来如何展开？

首版采用空间化目录：章节以路径、前后层级、尺度变化或具有纵深的节点关系组织。允许融入编辑式编号和短说明，但不能以平面列表作为主要呈现方式。

目录只承担开场导览和必要的临时跳转，不应每隔几页都返回。

#### `section-divider`

回答：我们进入了哪一个问题？

- 清楚呈现章节编号和一句章节命题；
- 以单一视觉对象、空间构图或景别变化建立章节记忆；
- 不在章节页堆叠正文和数据；
- 章节页的空间效果要与封面、目录属于同一套视觉语言。

### 5.2 叙事页

#### `headline-points`

回答：这个判断由哪些要点组成？

- 一个明确的大标题；
- 3–5 个短要点，每项尽量不超过两行；
- 重点通过字重、砖红、位置或留白表达，不依赖动画。

#### `statement`

回答：观众此刻应该记住什么？

- 一个核心判断；
- 一句限制或条件；
- 可选的小型引用或指标；
- 留白充足，不做缺少证据支撑的口号页。

#### `split-media`

回答：这张图或这段材料如何支持叙事？

- 使用稳定的左右或上下分栏；
- 可放图片、研究图、本地 SVG 或短视频；
- 图注、来源和材料角色清晰；
- 动态效果不得遮挡图例、标注或重要细节。

### 5.3 解释页

#### `process-flow`

回答：事情如何从 A 走到 B？

- 3–7 个节点；
- 横向步骤或简单分支；
- 连线关系明确，节点文字简短；
- 可有一轮轻量揭示，结束后所有步骤同时可读。

#### `timeline`

回答：变化在什么阶段发生？

- 3–6 个节点；
- 明确区分真实时间与概念阶段；
- 采用横线、轨迹或时间带，避免装饰压过时间信息。

#### `comparison`

回答：几个对象到底差在哪里？

- 使用表格或并列条形；
- 保留单位、样本、来源和限制；
- 高亮不能只依赖颜色；
- 不使用影响数据判断的 3D 倾斜。

### 5.4 数据页

#### `chart-focus`

首版优先支持折线、柱状和散点图。每页聚焦一个主要读数；坐标、单位、图例和来源在静止状态下可见；动画用于揭示，不做持续变化；重要数据不得被背景效果抢走。

#### `table-focus`

用于必须精确阅读的少量数据。建议初始不超过 6–8 行、5 列，行间留白充足；重点值可用字重、位置或砖红强调；页脚交代数据来源与示意边界。

### 5.5 媒体与结尾页

#### `video-focus`

- 使用本地短视频，不自动播放和发声；
- `P` 播放 / 暂停，`M` 静音；
- 离开页面时暂停并重置；
- 视频无法加载时仍显示说明、封面和来源。

#### `references`

- 正文短引与参考页共享来源 ID；
- 编号按首次引用顺序生成；
- 缺失来源明确显示“待补”，不伪造文献；
- 图注和素材来源不得挤在页面底部的极小字号中。

#### `closing`

- 一句收束，可选 Q&A 或下一步；
- 停留，不自动循环；
- 可回到封面建立的空间状态，但保持安静、开放。

## 6. 动态与视觉素材的使用原则

每个素材或效果都必须承担明确的内容角色，而不是仅因“好看”进入模板。

| 视觉能力 | 内容角色 | 适合场景 | 避免的用法 |
| --- | --- | --- | --- |
| 镜头推进 / 退远 | 建立观看路径与空间层级 | 封面到目录、章节转换 | 每页都做镜头运动 |
| 局部放大 / 镜头效果 | 聚焦材料细节 | 图片、研究图、章节转场 | 正文持续变形 |
| 粒子或形体变化 | 表达聚合、解构、状态变化 | 概念页、具象研究对象 | 随机粒子背景 |
| 线、节点与路径 | 表达关系、顺序和流程 | 目录、流程、时间线 | 无语义全屏线场 |
| 慢速空间背景 | 维持舞台的纵深感 | 封面、章节、结尾 | 图表和表格背景 |
| 路径绘制 / 错峰揭示 | 引导注意顺序 | 开场、流程、时间线 | 逐字播放长段文字 |
| 命题词变化 | 展示主题的可变维度 | 封面或结尾 | 每页循环换词 |

进入模板的资产应记录以下契约：

```text
assetId:
role: background / stage / diagram / marker / transition
allowedSlides:
contentQuestion:
visualWeight: low / medium / dominant
motion: static / reveal / slow-loop / user-triggered
fallback:
license:
```

所有动效都需要静态回退状态，并遵守减少动态效果偏好。循环动效仅用于少数舞台页面，正文、表格和数据页默认静态。

## 7. 统一版式系统

### 7.1 固定骨架

- 16:9 设计画布；
- 统一安全边距；
- 稳定的标题、正文和注记层级；
- 页码、章节标识、来源和图注的固定规则；
- 图表与媒体的安全区域；
- 每页有稳定 ID；
- 减少动态效果后仍完整可读。

### 7.2 允许变化

- 暖白与墨黑页面的分布；
- 标题与正文的版式关系；
- 视觉对象、图片、图表和流程内容；
- 在统一空间语言内变化的景别、裁切和前后层次；
- 按页面任务选择动效强度。

砖红是首版唯一主强调色，不因单页需要随意引入新的主题色。

### 7.3 不允许的做法

- 因文字过多而把字号缩到不可读；
- 为单页临时创造只使用一次的新页型；
- 添加无语义的粒子、发光边框或 HUD 标签；
- 用 3D 透视改变图表和数据判断；
- 把页面烘焙成不可编辑的整页截图；
- 让章节各自采用互不兼容的视觉语言；
- 把四张演示用 PNG / JPG 当作首版模板的必备或代表性资产。

## 8. 动效系统

### 8.1 动效角色

**镜头与空间转场**：用于封面进入目录、目录进入章节、章节边界和结尾。表达观察位置或空间层级变化，不采用每页翻转的形式。

**内容揭示**：用于语义块出现、图表绘制、流程节点进入和图片展开。揭示结束后内容保持稳定。

**环境循环**：仅用于封面、章节、结尾或极少数概念页。必须低频、低对比、可暂停；正文、表格和数据页默认静态。

### 8.2 动效档位

| 档位 | 使用场景 | 行为 |
| --- | --- | --- |
| `quiet` | 表格、引用、图表 | 直接出现或极短淡入 |
| `standard` | 正文、流程、图文 | 0.25–0.6 秒内容揭示 |
| `spatial` | 封面、目录、章节、结尾 | 0.8–1.6 秒的镜头与层级变化 |
| `reduced` | 减少动态效果 | 静态切换或极短淡入 |

封面进入目录的空间转场属于首版重点；其他页面不为保持“空间感”而强行加入动效。

## 9. 内容输入与 AI 工作流

内容源使用 Markdown，而不是要求用户直接编辑 JavaScript。

示例：

```markdown
## S04 | chart-focus
章节：03 / EVIDENCE
标题：一条曲线说明什么？
正文：这里写观众需要理解的因果关系。
图表：assets/charts/example.svg
图注：示意数据，不代表研究结论。
来源：[@source-01]
强调：第三阶段之后出现明显变化。
```

每页至少包括稳定页面 ID、页型、顺序、标题、正文或结论、资源路径，以及图注 / 来源 / 示意边界；主题参数为可选项，但不能借此覆盖首版已确认的色彩和空间语言。

AI 负责读取 Markdown、选择已有页型、检查内容容量、生成配置、替换资源路径、保持来源编号稳定、按页面 ID 修改，并检查整场叙事。AI 不得编造数据、伪造来源、临时创造布局，或把学习素材当成可再分发素材。

## 10. 与具体演示项目的边界

模板负责：

- 页面 ID 与页型契约；
- 首版 `editorial-spatial` 视觉主题；
- 开场、空间化目录、章节和结尾；
- 键盘翻页、全屏、减少动态；
- 图表、表格、流程、视频和引用的通用容器；
- 资产契约、离线运行与内容稿映射。

具体演示项目负责自己的研究问题、章节结构、文案、图表、示意数据、引用和领域视觉材料。具体演示可以使用模板的版式与空间语言，但不应将某个领域专属的图形、颜色或对象写成模板的通用要求。

首版只确认一套主题。其他主题方向属于其他模板的设计范围，不在本文件中规划为本模板的切换选项。

## 11. 第一阶段设计样稿

在继续实现页面和动画前，先设计并确认以下 8 张关键页：

1. `cover`：极简大标题、砖红强调、空间纵深与封面视觉锚点；
2. `contents`：延续封面空间关系的立体目录路径；
3. `section-divider`：章节命题、编号和单一空间对象；
4. `headline-points`：暖白正文、大标题和三个要点；
5. `split-media`：图像 / 研究图、图注与来源；
6. `chart-focus`：清楚可读的趋势图、主要指标与注记；
7. `process-flow`：节点、连线和顺序揭示；
8. `closing`：结论与开放的下一步。

这 8 张页先以静态设计稿确认网格、字体、留白、色彩、空间层级和整场节奏。封面与目录需额外验证空间连续性。确认后再实现 HTML 和动效。

## 12. 当前代码处理原则

设计稿确认以前：

- 不继续堆叠页面或动画；
- 不将演示用 PNG / JPG 强行包装成模板核心资产；
- 不把具体演示项目的领域视觉反向写成通用模板规则；
- 不以页面数量或特效数量作为模板进度指标。

下一阶段从静态样稿开始，先完成一场覆盖核心页型的短演示，再验证 Markdown 到演示配置的流程。

## 13. 验收标准

- 第一眼能看出这是演示文稿，而不是普通网页；
- 暖白、墨黑和砖红形成统一、克制的首版视觉系统；
- 极简风格下仍有明确的空间层次和立体感；
